### 2.1 `packages/i18n` (`@bricklap/i18n`)

- Pacote novo: `dictionary.ts` (forma `Dictionary`, tipo explícito, não derivado de `typeof`), `dictionaries/en.ts` (base) e `dictionaries/pt-PT.ts`, `translate.ts` (`createTranslator(dict)` → `t(key, params?)`, com `DictKey<T>` a gerar o tipo das chaves a partir do próprio dicionário), `locale.ts` (`resolveLocale`, `translatorFor`, `getDictionary`), `units.ts` (`UnitSystem`, `formatDistanceForUnit`/`formatSpeedForUnit`/`formatPaceForUnit`).
- Só depende de `@bricklap/engine` (tipo `Sport` + formatadores métricos) — zero dependências externas novas.
- `sport` no dicionário está indexado por `Sport`: um quinto desporto no motor obriga os dois dicionários a descrevê-lo antes do build passar.
- `resolveLocale(candidates)`: correspondência exacta primeiro, depois língua-base (`pt-BR` → `pt-PT`), senão `en`. Cada app junta os seus candidatos; o pacote não sabe nada de DOM nem de React Native.
- Unidades: `metric` delega direto nos formatadores do motor; `imperial` está no tipo `UnitSystem` mas lança (`"the imperial unit system is declared but not implemented yet"`) em vez de rotular metros como milhas.
- 25 testes em 4 ficheiros, cobertura 100%. Inclui uma verificação em runtime de que `en` e `pt-PT` têm exatamente o mesmo conjunto de chaves (a par da garantia do compilador).

## 5. Decisões tomadas e porquê

| Decisão | Porquê | Alternativa rejeitada |
|---|---|---|
| **`packages/i18n` como workspace novo**, não uma pasta dentro do lab ou do motor | Precisa de ser partilhado pelas duas apps e não pode viver no motor (que não pode ter texto de interface). Só depende do motor (tipo `Sport` + formatadores), zero dependências externas — não conta como "nova dependência" no sentido da regra da sessão. | Duplicar dicionários em cada app: garantiria divergência. |
| **Dicionário próprio tipado, não `i18next`** | Duas línguas, plurais simples, tudo conhecido em build-time. Ver `docs/adr/0004-i18n-dicionario-proprio.md` — critério explícito para trocar: mais de ~3 línguas ou plurais complexos. | `i18next` + `react-i18next`: dependências novas, API maior do que o produto precisa hoje. |
| **`t(key)` tipado por caminho com pontos**, verificado contra o dicionário | Corresponde à API pedida (`t("session.start")`) e dá erro de compilação numa chave em falta ou mal escrita — não uma string em branco descoberta a testar a app. | Ficheiros JSON soltos sem tipo: perde a verificação em compilação. |
| **Deteção de locale por API nativa** (`I18nManager` no Android, `navigator.languages` no browser), sem `expo-localization` | Zero dependências novas; a informação já está disponível nas duas plataformas. | `expo-localization`: dependência extra só para um valor que já existe. |
| **`pt-BR` cai em `pt-PT`**, não em inglês | Melhor experiência para um utilizador de português do que mostrar inglês, mesmo sem dicionário `pt-BR` próprio. Documentado como decisão explícita a rever. | Cair sempre em inglês: pior experiência sem ganho de rigor. |
| **`SPORT_META` renomeado para `SPORT_PACE_KIND`**, não só encolhido com o mesmo nome | O nome antigo prometia "metadados"; hoje só há lógica de ritmo. Um nome preciso evita confundir quem vier a acrescentar de novo um rótulo ali por engano. | Manter o nome `SPORT_META` com forma menor: nome deixaria de corresponder ao conteúdo. |
| **Unidades: métrico implementado, imperial só declarado no tipo** | Pedido explícito da sessão. Lançar em vez de fingir converter evita números errados silenciosos. | Implementar já a conversão: fora do pedido desta sessão; ou ignorar o pedido de "declarar": perderia o sítio já pronto para a preferência. |
| **`apps/web-lab/README.md` fica com o caminho relativo** (não qualificado) no mapa do repositório | É a única entrada dessa lista que seria absoluta se eu seguisse a instrução à letra; todas as outras (`src/routes/`, `src/lib/store.ts`, …) são relativas a `apps/web-lab/`. Corrigi as dúvidas genuínas (LEGAL.md, legal.index.tsx, ambos lidos fora desse contexto) e mantive a consistência do README. | Qualificar as quatro: quebra o padrão do resto da lista sem ganho real (o README já diz onde está). |
| **Não correr `eas login`** | Instrução explícita: credenciais nunca passam por aqui. | — |
| **`nvm use default` acrescentado ao `~/.bashrc`** | Ajuda sessões futuras (interativas) a arrancarem já em Node 24; não tem efeito nesta sessão (bashrc só corre a parte do `nvm` em shells interativas), por isso todos os comandos desta sessão prefixaram o `PATH` à mão. | Nada: sem isto, sessões futuras continuam em Node 23 até alguém reparar. |
